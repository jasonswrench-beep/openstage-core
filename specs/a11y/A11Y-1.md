# A11Y-1: the OpenStage accessibility rules

Revision 1.0, 2026-11-16. Catalogue [`rules.json`](rules.json). Measured against **WCAG 2.1, level AA**.

One set of accessibility rules for every OpenStage tool: the same rule ids, the same words, the same contrast
arithmetic, the same report, and the same project setting for the rules an author wants to stop publishing. Each tool
checks two kinds of thing with it:

- **Its own project** (a course's objects, a book's pictures, a guide's steps). Only the tool knows its project, so it
  writes those checks itself, using the catalogue's ids and words ("source" checks; section 6.7).
- **What it made** (a web page, a help site, an EPUB, a Word or PowerPoint file, a captions file, a PDF). The
  **engine**, `openstage-a11y`, checks these; the tool gives it the file.

**Findings warn. Nothing in these rules stops a person working, exporting or publishing**, unless that person turned
a rule into a blocker for their own project (section 5). A tool must work in full with every finding open.

The implementations in this repository:

| | What | Where |
|---|---|---|
| The engine | A Rust library and a command-line program: checks a file or a folder and returns a report (section 4). | [`crates/openstage-a11y`](../../crates/openstage-a11y), tag `a11y-v0.1.0` |
| The package | JavaScript with no dependencies, for an editor: the catalogue, the status words, contrast, findings, the settings. It does not read files. | [`packages/a11y`](../../packages/a11y) (`@openstage/a11y`) |
| The test set | 20 small inputs with the findings each must give, worked out by hand. | [`testsets/a11y`](../../testsets/a11y) |
| Contrast cases | Ratios, text results and blends both implementations must agree on. | [`conformance/contrast.json`](conformance/contrast.json) |

## 1. Words used here

**Rule**: one thing that is checked, with a stable id such as `alt-missing`. **Finding**: one place where a rule
found something, with a status. **Report**: everything one check found. **Machine rule**: a rule a program can
check. **Person rule**: a check only a person can make (reading order, what a description says); it is listed in the
report's checklist and never has a status. **Blocker**: a rule a project chose to stop publishing.

## 2. The catalogue

[`rules.json`](rules.json) holds the statuses, the WCAG 2.1 success criteria named, and every rule:

| Member | |
|---|---|
| `id` | Stable: never renamed, never given to another rule, never reused once dropped. A person ignores a rule, or makes it a blocker, by its id. |
| `kind` | `machine` or `person`. |
| `title` | A plural noun phrase for a list heading ("Pictures with no description"). For a person rule, an instruction ("Check the reading order"). |
| `wcag` | The success criteria it serves, by number. Empty for a practice outside WCAG (EPUB's accessibility details). |
| `basis` | `requirement` when a WCAG 2.1 AA success criterion asks for it; `practice` when it is good practice that serves one (a skipped heading level; a slide with no title). A practice finding still uses `fail` or `needs-review`; a tool may show the basis. |
| `checks` | Where it can be checked: `source` (a tool's own project), `html`, `epub`, `docx`, `pptx`, `pdf`, `vtt`. |
| `message` | What was found, in plain words; `{name}` is filled from the finding's `params`. |
| `variants` | Other messages for the same rule, by name (`page-title` has `placeholder`). |
| `fix` | What to do about it, with the same `{name}` filling. Every machine rule has one. |

The words are plain English with no long dashes. A change to a rule's words is a new revision of the catalogue; a new
rule, or a rule that checks more, is a new revision too, and the changes log says what changed.

`rules.json` here is the one to change. `node tools/sync_a11y_rules.mjs` copies it to the engine and the package, and
the core's checks fail while a copy differs.

## 3. Contrast

### 3.1 The ratio

A colour is three 8-bit sRGB values. Each value `v` is made linear: `s = v / 255`, then `s / 12.92` when
`s <= 0.04045`, otherwise `((s + 0.055) / 1.055) ^ 2.4`. The relative luminance is `0.2126 R + 0.7152 G + 0.0722 B`.
The contrast ratio of two colours is `(L1 + 0.05) / (L2 + 0.05)`, the lighter's luminance over the darker's.

WCAG 2.1 writes the knee as 0.03928; WCAG 2.2 and the sRGB standard write 0.04045. No 8-bit value lies between them,
so both give the same result for every colour here; implementations use 0.04045.

The ratio is **compared unrounded**: 4.499 to 1 fails 4.5 to 1. In words it is **rounded down** to one decimal place,
so a failing 4.49 reads "4.4 to 1" and never "4.5 to 1".

### 3.2 The minimums

| | Minimum | Success criterion |
|---|---|---|
| Text | 4.5 to 1 | 1.4.3 |
| Large text: at least 18 points, or at least 14 points and bold | 3 to 1 | 1.4.3 |
| A mark, an icon, or the edge of a control, against what is next to it | 3 to 1 | 1.4.11 |

**Bold** is a weight of 700 or more. **Points**: a CSS pixel is 0.75 points, so large text is 24px, or 18.67px and
bold (14 points is 18.666... px; 18.66px bold is not large). In Word a size is in half-points, in PowerPoint in
hundredths of a point.

**Weight not known** (some PDFs): counted as normal, except that text of at least 14 and under 18 points whose ratio
is at least 3 and under 4.5 to 1 **needs review** (variant `uncertain-bold`), because it passes only if it is bold.

### 3.3 See-through colours

A colour with alpha `a` (0 to 1) over another: each channel is `a * top + (1 - a) * under`, **rounded to the nearest
whole value** before its luminance is taken. A see-through background is laid over what is behind it, and see-through
text over its background. An element's opacity multiplies its text's alpha.

### 3.4 When the background cannot be measured

Text over a picture or a gradient: the finding **needs review**, variant `unknown-background`. It is never a pass.

## 4. The report

### 4.1 Statuses

| Status | Word | Symbol | |
|---|---|---|---|
| `pass` | Pass | ✓ | Checked, and nothing found. |
| `fail` | Fail | ✗ | Found. |
| `needs-review` | Needs review | ? | Found something a person must judge (a vague link may be clear in its sentence). |
| `not-tested` | Not tested | ○ | The rule applies but could not be checked here; `reason` says why. |
| `not-applicable` | Not applicable | – | Nothing of the kind is there (no pictures, no tables). |

These are PDF Remediator's status words. A status is always shown with its word, or its word and its symbol, **never
by a colour alone**.

### 4.2 A finding

```json
{
  "rule": "contrast-text",
  "status": "fail",
  "wcag": ["1.4.3"],
  "basis": "requirement",
  "where": { "file": "index.html", "id": "muted", "element": "html/body/main[1]/p[1]", "line": 9 },
  "key": "contrast-text index.html#id=muted",
  "message": "#999999 on #FFFFFF is 2.8 to 1; normal text needs at least 4.5 to 1.",
  "fix": "Make the text darker or its background lighter (or the other way round) until they reach 4.5 to 1.",
  "params": { "foreground": "#999999", "background": "#FFFFFF", "ratio": "2.8", "minimum": "4.5", "size": "normal" },
  "count": 1
}
```

- `where` has only the members that apply: `file` (a path inside what was checked, with `/`), `id` (an element's
  id), `element` (an element's path, each step its name and, in brackets, which one of that name under its parent,
  from 1; `html`, `head` and `body` have no number), `line`, `page`, `slide`, `object` (a tool's own id for a thing in
  its project, or a name such as "paragraph 3" or "table 1" in a Word file), and `scheme` (`dark` for a finding made
  under the dark colour scheme only).
- `key` is the rule id, a space, and the location: the file; then `#` and the first of `id=…`, the element path,
  `page=…`, `slide=…`, `object=…` and `line=…` that is set; then `@` and the scheme when there is one. The key stays the
  same between checks while the thing does not move, so a person can ignore one finding by it (section 5).
- `variant` is written when the message is one of the rule's variants.
- `count`: places with the same finding are folded into one (the same two colours across a page; the same style rule
  reached from several pages), the first place in `where`.

### 4.3 Rule results

The report lists every machine rule whose `checks` includes the kind of file, with `checked` (how many things it
looked at), `fail` and `needsReview` (counting each place) and a status: `fail` if any finding fails; otherwise
`needs-review` if any needs review; otherwise `not-tested` if it could not be checked; otherwise `pass` if it looked
at anything; otherwise `not-applicable`.

### 4.4 The rest of a report

```json
{
  "format": "A11Y-1", "revision": "1.0",
  "engine": { "name": "openstage-a11y", "version": "0.1.0" },
  "input": { "name": "site", "kind": "site", "files": 4 },
  "summary": { "fail": 6, "needsReview": 1, "rulesFailed": 4, "rulesNeedReview": 1, "rulesPassed": 7,
               "rulesNotTested": 0, "rulesNotApplicable": 15, "checklist": 3, "ignored": 0 },
  "rules": [ ... ], "findings": [ ... ],
  "checklist": [ { "rule": "reading-order", "title": "Check the reading order", "wcag": ["1.3.2"], "message": "..." } ],
  "limits": [],
  "blocking": []
}
```

(The test set's `site` case, as the engine reports it; the finding in 4.2 is one of its findings.)

- `input.kind`: `html`, `site` (a folder of pages), `epub`, `docx`, `pptx`, `pdf`, `vtt`. `files`: what was read.
- `checklist`: the person rules that apply to what was found (always reading order and colour; what descriptions say
  when there are pictures; the keyboard when there is something to press; captions and flashing when there is video).
- `limits`: in plain words, what the check could not do (a style sheet it could not read, rules inside a media query it
  does not follow, a page that runs scripts). A report never claims more than it checked.
- **The summary line** for an export's report: `Web page: 0 failures, 2 to review, 3 checks for a person`.

## 5. A project's settings

A project file keeps the author's choices under one member, `accessibilityChecks`:

```json
"accessibilityChecks": {
  "ignored": ["link-vague"],
  "ignoredFindings": ["contrast-text index.html#id=logo"],
  "blockers": []
}
```

| Member | Default | |
|---|---|---|
| `ignored` | `[]` | Rule ids whose findings are left out of the report and the counts (and counted in `summary.ignored`). |
| `ignoredFindings` | `[]` | Finding keys left out, one place at a time. |
| `blockers` | `[]` | Rule ids that stop publishing while one of their findings **fails**. |

1. **Every list is empty unless the author fills it.** With no `accessibilityChecks`, or empty lists, nothing blocks.
   A tool must not fill `blockers` for the author, suggest that it is required, or turn it on with another setting.
2. Only a finding that **fails** blocks. `needs-review` never blocks, since only a person can settle it, and neither
   does `not-tested`.
3. A rule that is a blocker is not hidden by `ignored` (the stricter choice was made on purpose); one of its findings
   can still be ignored by its key, which is how an author accepts one place.
4. When publishing is blocked, the tool says which findings block it, in the finding's words, and how to turn the
   blocker off. The rule's status in the report is what was measured; settings do not change it.
5. A reader skips values in the lists that are not strings, keeps members of `accessibilityChecks` it does not
   know, and writes the member back unchanged apart from what the author changed. A tool's format change that adds
   the member is a format version with a migration, as each tool's format rules ask.
6. The engine reads the member from a project file (`openstage-a11y check <file> --project project.json`); the package
   reads it with `readSettings(project)`.

## 6. What the engine checks

### 6.1 A web page, and a help site (`html`, `site`)

A single `.html` file, or a folder: every `.html`, `.htm` and `.xhtml` file in it and its sub-folders (not hidden
folders), with the local style sheets each page links to (never outside the folder). Each page:

| Rule | What fails or needs review |
|---|---|
| `page-lang` | No `lang` (or `xml:lang`) on `html`; or one not shaped like a language tag (two or three letters, or `x`/`i` and more, then parts of one to eight letters and digits, joined by hyphens: `en`, `en-US`, `zh-Hant-TW`; `en_US` and `english` fail). |
| `page-title` | No `title`, or a placeholder (`Untitled`, `Document`, `Page`, `Index`, a file name, no letters). |
| `alt-missing` | An `img` with no `alt` and no other name; an image button, an image map area, or an element with `role="img"` (an SVG) with no name. `alt=""` is decorative and fine; an element hidden from screen readers is skipped. |
| `alt-weak` | A description that is a placeholder: a word that names the kind of thing (`image`, `photo`, `picture 3`, `logo`, `screenshot`...), a file name, the picture's own file name or its stem, or no letters. |
| `alt-decorative-text` | A picture marked decorative (`role="presentation"` or `none`) that also has a description. |
| `heading-empty` | A heading (`h1`-`h6`, or `role="heading"`) with no name. |
| `heading-start` | The first heading is not level 1. |
| `heading-order` | A heading more than one level below the one before it (2 then 4). |
| `control-name` | A button, field, list, or element with a widget role, with no accessible name (`aria-labelledby`, `aria-label`, a label, the content for a button, `title`, `placeholder`). |
| `link-name` | A link with no name. |
| `link-vague` (needs review) | A link whose words are only: here, click here, click, more, read more, learn more, more info, info, link, this link, this, details, go, this page, page, website, see more, continue reading. |
| `id-duplicate` | An id used more than once (once a page, at its first use). |
| `id-reference` | `aria-labelledby`, `aria-describedby`, `aria-controls`, `aria-owns`, `aria-flowto`, `aria-details`, `aria-activedescendant`, `aria-errormessage`, a label's `for` or a cell's `headers` naming an id that is not on the page. |
| `role-unknown` | A `role` none of whose words is an ARIA 1.2 role, a DPUB-ARIA role (`doc-...`) or a graphics role. |
| `landmark-main` | No `main` element or `role="main"`. |
| `bypass-blocks` | A skip link (an in-page link among the first three things that take the focus) that goes to an id that is not there (variant `skip-target`); or a page with navigation and no main part, no headings and no skip link. |
| `contrast-text` | Text under its minimum (section 3), in the light scheme and, when the page has dark-scheme rules or says it supports a dark scheme, in the dark scheme too (`where.scheme` is `dark`). Text over a picture or gradient needs review. Hidden text, text hidden for the eye only, disabled controls, and text in SVG are left out. |
| `keyboard-reach` | Something with a click handler (`onclick`, `onmousedown`, `onmouseup`) that cannot take the focus; a link or control taken out of the Tab order with `tabindex="-1"` needs review (variant `removed`). |
| `keyboard-operate` (needs review) | Something made focusable with `tabindex` that has a click handler and no key handler. |
| `focus-order` (needs review) | A positive `tabindex`. |
| `focus-visible` (needs review) | A style rule that takes the focus outline away (`outline: none` or `0`) from something on the page that takes the focus, without a border, shadow or other outline in the same rule, a later focus rule for it, or a `:focus-within` rule on it or a box around it that shows focus. |
| `captions-missing` | A `video` with no `track` of kind `captions` or `subtitles` (a track with no kind counts as subtitles). An embedded video (YouTube, Vimeo and other players) needs review (variant `embedded`). |
| `audio-description` (needs review) | A `video` with no `track` of kind `descriptions`. |
| `transcript-missing` (needs review) | An `audio` with no "transcript" in the words around it. |
| `media-autoplay` | `audio` or `video` that starts by itself, not muted and with no controls. |
| `timed-content` | A `meta` refresh after more than 0 seconds (variant `refresh`); a `marquee` or `blink` (variant `moving`). |
| `table-headers` | A table of at least two rows and two columns, not marked as layout (`role="presentation"`), with no `th`, no `scope` and no header role. |

**The style the engine follows:** style sheets linked and in `style` elements, and `style` attributes; selectors of
names, ids, classes, attributes, `:root`, `:link`, `:first-child`, `:last-child`, `:not()`, `:is()` and `:where()`
of those, joined by descendant and child combinators; specificity, order and `!important`; inheritance; custom
properties and `var()`; `@media` for the colour scheme (and `screen`, `all`), `@supports` and `@layer` blocks; the
browser's own colours for links, buttons, fields and `mark`, and its sizes and weights for headings. Not followed,
and said so in `limits` when it may matter: sibling combinators and other pseudo-classes, `@import`, media queries by
width, and anything a script changes. Print styles, forced colours and more-contrast modes are not the page's default
look and are left out silently.

### 6.2 An EPUB 3 (`epub`)

The package file: `page-title` (`dc:title`), `page-lang` (`dc:language`), `bookmarks` (a navigation document with an
`epub:type="toc"` list), and `ebook-metadata` (EPUB Accessibility 1.1: `schema:accessMode`,
`schema:accessibilityFeature`, `schema:accessibilityHazard` and `schema:accessibilitySummary`; the finding lists those
missing). Then each content document in the spine as a page (section 6.1, without `landmark-main` and
`bypass-blocks`, which a reading system provides), with the book's style sheets. **The headings of the whole book are
one outline**, so `heading-start` and `heading-order` look across chapters.

### 6.3 A Word file (`docx`)

| Rule | What fails or needs review |
|---|---|
| `page-title` | No title (or a placeholder) in the document properties (`docProps/core.xml`). |
| `page-lang` | No language in the default run properties (`styles.xml`) or the theme font language (`settings.xml`). |
| `heading-empty`, `heading-start`, `heading-order` | Headings are paragraphs with an outline level, set on the paragraph or its style (through `basedOn`), or a style named "heading 1" to "heading 9". The style named Title counts as level 1. Where: `object` "paragraph N", counting every paragraph of the body, those in tables too, from 1. |
| `alt-missing`, `alt-weak` | Each picture, chart and diagram (`wp:docPr`) with no description and not marked decorative, or a placeholder description; Word's own made-up description ("... Description automatically generated") needs review. Where: `id`, the drawing's id. Old (VML) pictures with no `alt`. |
| `table-headers` | A table of at least two rows and two columns whose first row is not set to repeat as a header row. Where: `object` "table N". |
| `link-name`, `link-vague` | A link with no words and no described picture; a link whose words are vague (the list of 6.1, shorter). Where: `object` "link N". |
| `contrast-text` | A run whose colour is set (on the run, its character style, or its paragraph style) against its shading or highlight, the paragraph's or the table cell's shading, or the page colour, else white. Text left to "automatic" colour is not checked, since Word picks black or white for it. |

### 6.4 A PowerPoint file (`pptx`)

`page-title` (document properties), `page-lang` (a `lang` on the text), `slide-title` (each slide has a title or
centred-title placeholder with words; where: `slide`), `alt-missing` and `alt-weak` (each picture, chart and diagram,
by its shape id), `table-headers` (a table of two rows and two columns or more without "header row" on), `link-vague`,
`captions-missing` (a video needs review, variant `unknown`, since captions inside a presentation are not read), and
`contrast-text` for text whose colour and background (the shape's fill or the slide's background) are both written as
colours. Colours from the theme are not read, and `limits` says so.

### 6.5 A WebVTT captions file (`vtt`)

`captions-format` fails when the file does not start with `WEBVTT`, when a cue's times cannot be read, or when a cue
ends before it starts (the first such problem, by line). `captions-reading` needs review, one finding a caption, the
first of: it starts before the one before it ends (`overlap`); it has more than 2 lines (`lines`); a line is longer
than 42 characters (`line`); it shows more than 20 characters a second (the default message). Characters are counted
with the cue's tags left out. Where: the line of the cue's times.

### 6.6 A PDF (`pdf`)

**Not in engine 0.1.** A PDF's rules (`pdf-tagged`, `pdf-title-shown`, `page-title`, `page-lang`, `alt-missing`,
`heading-*`, `table-headers`, `bookmarks`, `contrast-text`, ...) are reported `not-tested` with that reason. PDF
Remediator checks PDFs today, with these status words and this contrast arithmetic; its checks come into the engine
in a later revision.

### 6.7 A tool's own project (`source`)

A tool checks its own project with its own code, and reports with the catalogue's ids, words and statuses (the
package's `finding()` fills them). It uses `where.object` with its own ids. Rules most tools need here:
`alt-missing`, `alt-weak`, `alt-decorative-text`, `contrast-text` and `contrast-graphic` (marks, icons and outlines:
3 to 1), `keyboard-reach`, `keyboard-operate`, `focus-order` (variant `duplicate`: two things share a place),
`focus-order-gaps`, `captions-missing`, `audio-description`, `timed-content`, `slide-title`, `captions-reading`. A
tool's checks that are not about accessibility (an empty topic, a missing file) keep their own ids outside A11Y-1.

## 7. Checking an implementation

- **The test set**: `node testsets/a11y/check/check_engine.mjs --engine <program>` runs any program that takes
  `check <input> --json` and prints a report, on each case, and compares the findings (exactly: none missing, none
  extra, the same status, variant, count and the listed values), the listed rule statuses, summary numbers, checklist
  and limits. The engine's own tests run the same comparison.
- **The contrast cases**: [`conformance/contrast.json`](conformance/contrast.json), which the engine and the package
  both pass.
- A tool's own source checks have no shared set; a tool shows its checks use the catalogue's ids and words in its own
  tests.

## 8. Where the tools differ today (2026-11-16)

For the rounds that move each tool onto these rules:

- **OpenStage Author**: its validator stops a publish on an accessibility error ("Accessibility problems are errors,
  not warnings"). Under section 5 they warn, and stop a publish only when the author made the rule a blocker; that is
  priority 4. Its ids map as: `alt-text-missing` → `alt-missing`; `alt-text-on-decorative` → `alt-decorative-text`;
  `not-keyboard-reachable` → `keyboard-reach`; `click-without-key` → `keyboard-operate`; `tab-order-duplicate` →
  `focus-order` (variant `duplicate`); `tab-order-gaps` → `focus-order-gaps`; `media-needs-captions` →
  `captions-missing`; `contrast` → `contrast-text`; `icon-contrast` → `contrast-graphic`; `table-needs-header` →
  `table-headers`. Its large-text cut-off is 18.66px bold; A11Y-1's is 14 points (18.67px), so 18.66px bold text is
  normal here.
- **OpenExplainer**: its book check keeps its own kinds; the accessibility ones map as `picture-alt` and `logo-alt` →
  `alt-missing`; `mark-alt` → `alt-missing` (a mark is a picture's part with its own description); `mark-contrast` →
  `contrast-graphic`; `look-contrast` → `contrast-text`; `callout-name` → `control-name`; `vague-link` →
  `link-vague`. Its ignored kinds become `accessibilityChecks.ignored` with these ids.
- **PDF Remediator**: the status words are its own. Its language check accepts a first part of two to eight letters;
  A11Y-1 accepts two or three (or `x`/`i`), which catches `english` and `en_US`.
- **Capture Express**: its export tests (one `h1`, no skipped heading, alt text, colours of 4.5 to 1) become a run of
  the engine on each export, with the summary line in the export report.
